คุณคือนักพัฒนาในทีม งานของคุณคือ **ทำ task ต่อเนื่องทีละตัวตามลำดับใน tasks.md จนจบ 1 เฟส แล้วหยุดที่จุดตรวจ** ให้ทีมลองระบบเองก่อนไปเฟสถัดไป

ทำทีละ task เหมือน /implement ทุกอย่าง ต่างกันแค่ทำต่อให้เองจนจบเฟส และ commit ให้ทีละ task

## ขั้นที่ 0: หาไฟล์ เลือกเฟส และเช็กฐานก่อนเริ่ม

- ถ้าผู้ใช้ระบุ path ของ tasks.md ให้ใช้ไฟล์นั้น ถ้าไม่ระบุ ให้หา `specs/*/tasks.md` ถ้ามีหลายไฟล์ให้ถาม
- อ่าน `tasks.md`, `spec.md`, `plan.md` ในโฟลเดอร์เดียวกัน และ `AGENTS.md` ให้จบ
- ถ้ามีโฟลเดอร์ `specs/000-shared/` ให้อ่านทุกไฟล์ .md ในนั้นด้วย (constraints.md, data-model.md, glossary.md) Constraint ที่ spec ฟีเจอร์เขียนว่า "ใช้ร่วม" มีข้อความเต็มอยู่ที่นั่น และ**นับเป็น Constraint ของฟีเจอร์นี้ทุกข้อ**
- task หน้าจอที่มีช่อง "แบบหน้าจอ" ให้เปิดไฟล์ mockup นั้น และอ่านหมวด "หน้าจอ (UI)" ใน spec ก่อนทำ task นั้น
- ถ้า tasks.md **ไม่ได้แบ่งเป็นเฟส** (ไม่มีหัวข้อ "## เฟส") ให้หยุด แล้วบอกทีมว่าให้รัน /tasks ใหม่ให้แบ่งเฟสก่อน หรือใช้ /implement ทีละตัว
- ถ้าผู้ใช้ระบุ "เฟส N" ให้ทำเฟสนั้น ถ้าไม่ระบุ ให้เลือกเฟสแรกที่ยังมี task สถานะ "พร้อมทำ"
- ถ้าเฟสก่อนหน้ายังมี task ที่สถานะไม่ใช่ "เสร็จ" (เช่น "เสร็จ รอทีมตรวจ") ให้หยุดถาม เพราะทีมยังไม่ได้ผ่านจุดตรวจของเฟสนั้น
- ถ้าเป็นเฟส "รอคำตอบ" ให้ปฏิเสธ และบอกว่าต้องปิด Q-xx ใน spec ก่อน
- รัน test ทั้งหมดที่มีอยู่ 1 รอบก่อนเริ่ม (หลังบ้าน `cd backend && pytest` หน้าจอ `cd frontend && npm test` ถ้ามีโฟลเดอร์นั้น) ถ้ามีตัวไหนไม่ผ่านตั้งแต่ก่อนเริ่ม ให้หยุดและรายงาน ห้ามทำงานต่อบนฐานที่พัง

## ขั้นที่ 1: วนทำทีละ task ตามลำดับในเฟส

สำหรับแต่ละ task ในเฟส เรียงตามลำดับในไฟล์

1. ตรวจ 3 อย่าง: สถานะเป็น "พร้อมทำ" / task ในช่อง "ต้องทำหลัง" เสร็จแล้ว (นับ "เสร็จ รอทีมตรวจ" ที่คุณทำในรอบนี้ได้) / ช่อง "ไฟล์ที่แตะ" และ "เสร็จเมื่อ" ไม่ว่าง
2. ทำงานตามกติกาเดียวกับ /implement ทุกข้อ
   - สร้างหรือแก้เฉพาะไฟล์ในช่อง "ไฟล์ที่แตะ" ของ task นั้น
   - ใช้เทคโนโลยีตาม plan.md เท่านั้น ห้ามเพิ่มฟีเจอร์ ห้ามแตะ Out of scope
   - test ชื่อมี AC ID แปล Given / When / Then ของ AC เป็นขั้นตอนใน test ตรง ๆ
   - ทุกฟังก์ชันหลักมีคอมเมนต์ว่ารองรับ FR / CON / IF ข้อใด
   - ตัวเลขและกฎที่มาจาก spec ใช้ค่าจาก `backend/app/config.py` พร้อมคอมเมนต์อ้าง ID ห้ามฝังตัวเลขในโค้ดโดยตรง
   - **task หน้าจอที่มี mockup** (ช่อง "แบบหน้าจอ" ไม่ใช่ "ไม่มี"): สิ่งที่หมวด "หน้าจอ (UI)" ใน spec บอกว่า "ต้องตรง" (ชื่อช่อง ลำดับ ข้อความ) ต้องตรงกับ mockup ทุกตัวอักษร ส่วนที่ "ยืดหยุ่นได้" ใช้ style ของโปรเจกต์ได้ เขียนเป็น component ตาม plan **ห้ามคัดลอกไฟล์ mockup ทั้งไฟล์มาเป็นโค้ด** ห้ามเอาข้อมูลตัวอย่างใน mockup มาใส่ตายตัวในโค้ด และถ้า mockup มีปุ่ม ช่อง หรือข้อความที่ไม่มี FR รองรับ หรือเป็นเรื่องที่ยังเป็น Q-xx ห้ามสร้าง ให้หยุดแจ้งทีม
   - **ห้ามแก้หรือลบ test ที่ชื่อขึ้นต้นด้วย `test_TC_` หรือไฟล์ `TC-*.test.jsx`** (มาจาก test-cases.md) ถ้าไม่ผ่านให้แก้โค้ด ถ้าคิดว่า test ผิดให้หยุดถามทีม
3. รัน test **ทั้งหมด** ของโปรเจกต์ ไม่ใช่แค่ test ของ task นี้ เพื่อเช็กว่าไม่ทำของเดิมพัง แสดงผลให้ทีมเห็น
4. ถ้าผ่านทั้งหมด
   - เปลี่ยนสถานะ task นี้ใน tasks.md เป็น "เสร็จ รอทีมตรวจ"
   - เพิ่มบันทึกท้าย `prompt-log.md` (ต่อท้ายเท่านั้น): /implement-all เฟส N, task, ไฟล์ที่แตะ, ผล test
   - commit ทีละ task: `git add -A && git commit -m "T-xx <ชื่อ task> (implement-all)"` **ห้าม push**
5. ไป task ถัดไปในเฟสเดียวกัน

## ขั้นที่ 2: หยุดทันทีเมื่อเจอข้อใดข้อหนึ่ง (ห้ามข้ามไปทำตัวอื่นแทน)

- test ไม่ผ่าน หลังแก้ภายในไฟล์ของ task แล้ว 3 รอบ
- test ของ task ก่อนหน้าที่เคยผ่าน กลับไม่ผ่าน และแก้ภายในไฟล์ของ task ปัจจุบันไม่ได้
- เจอ task สถานะ "รอ Q-xx"
- ต้องเดาสิ่งที่ spec และ plan ไม่ได้บอก
- ต้องแตะไฟล์นอกช่อง "ไฟล์ที่แตะ"
- ทำไปแล้ว 5 task ในรอบนี้ (กันงานก้อนใหญ่เกินกว่าทีมจะตรวจไหว)
- ทำครบทุก task ในเฟสแล้ว (หยุดที่จุดตรวจ)

**ห้ามเริ่ม task ของเฟสถัดไปเด็ดขาด** แม้จะเหลือเวลา

## ขั้นที่ 3: รายงานที่จุดตรวจ

1. ตาราง `task` | `ไฟล์ที่แตะ` | `test` | `ผล` | `commit`
2. ผล test ทั้งหมดรอบสุดท้าย
3. หยุดเพราะอะไร (ครบเฟส หรือเงื่อนไขข้อไหนในขั้นที่ 2)
4. คัดบล็อก "จุดตรวจเฟส N" จาก tasks.md มาให้ทีมทำตาม: คำสั่งเปิดระบบ และ Given / When / Then ให้คนลองเอง
5. บอกทีม 2 ทาง
   - ลองเองผ่าน: เปลี่ยนสถานะ task ในเฟสนี้เป็น "เสร็จ" แล้ว `git push` จากนั้นสั่ง /implement-all เฟสถัดไป
   - ลองเองไม่ผ่าน: ดู commit ด้วย `git log --oneline` แล้วสั่งแก้ทีละ task ด้วย /implement หรือย้อน commit ที่ผิดด้วย `git revert <รหัส commit>`
