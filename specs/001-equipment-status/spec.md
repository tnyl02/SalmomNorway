# Feature: ตรวจสอบสถานะอุปกรณ์ (Equipment Status)
Spec ID: SPEC-EQS-001 | Source: US-001, Service Blueprint เฟส "ตรวจสอบอุปกรณ์ที่ต้องการยืม" | Use case: UC-01
Owner: - | Status: Draft v2 | Updated: 2569-09-20

## Goal
นักศึกษาที่ยืนยันตัวตนแล้ว ค้นหาและตรวจสอบสถานะอุปกรณ์ของภาควิชาได้ด้วยตนเองภายใน 1 นาที
โดยไม่ต้องเดินไปสอบถามเจ้าหน้าที่ (เดิมใช้เวลา 5-10 นาที) และเจ้าหน้าที่ลดภาระการตอบคำถามซ้ำ

## Scope
### In scope
- แสดงรายการอุปกรณ์แบบจัดกลุ่มตามรุ่น/ชนิด พร้อมจำนวนที่พร้อมให้ยืม/ทั้งหมด และสถานะล่าสุดรายชิ้น
- ค้นหาด้วยชื่อ/รหัสอุปกรณ์ และกรองตามประเภทและสถานะ
- แสดงรายละเอียดอุปกรณ์รายชิ้น รวมกำหนดคืนโดยประมาณกรณีถูกยืมอยู่
- แสดงข้อมูลตามสิทธิ์ของผู้ใช้ (นักศึกษา / เจ้าหน้าที่ / อาจารย์หัวหน้าโครงการ)
### Out of scope
- ส่งคำขอยืม (UC-02) | บันทึกส่งมอบ (UC-08) | บันทึกการคืน (UC-09) | จัดการสถานะอุปกรณ์ (UC-10)
- ยืนยันตัวตน (UC-13) - ถือว่าทำสำเร็จแล้วก่อนเข้าฟีเจอร์นี้ (precondition)
- จองอุปกรณ์ล่วงหน้า - ยังไม่มีใน use case diagram (ดู Q-02)

## Constraints
- CON-TECH-01 ใช้ฐานข้อมูล PostgreSQL ตาม Infrastructure ที่กำหนดไว้
- CON-TECH-02 ให้บริการผ่าน HTTPS เท่านั้น deploy ด้วย Docker บน on-campus server หรือ cloud VM
- CON-DATA-01 สถานะอุปกรณ์มีค่าที่เป็นไปได้ 6 ค่าเท่านั้น: พร้อมให้ยืม, รออนุมัติ, ถูกยืม,
  ซ่อมบำรุง, ชำรุด, สูญหาย
- CON-DATA-02 ฟีเจอร์นี้เป็น read-only ไม่มีการเปลี่ยนสถานะอุปกรณ์จากที่นี่
  สถานะถูกเปลี่ยนโดย UC-07 (อนุมัติ), UC-08 (ส่งมอบ), UC-09 (คืน), UC-10 (เจ้าหน้าที่ปรับเอง)
- CON-DATA-03 อุปกรณ์แต่ละชิ้นมีรหัสครุภัณฑ์ไม่ซ้ำกัน แม้เป็นรุ่นเดียวกัน
- DOM-PRIV-01 นักศึกษาเห็นได้เฉพาะสถานะและกำหนดคืนโดยประมาณ ไม่เห็นชื่อผู้ยืมรายอื่น
- DOM-AUDIT-01 บันทึก audit log ทุกครั้งที่เข้าถึงข้อมูลอุปกรณ์ (ผู้เข้าถึง, เวลา, เงื่อนไขที่ค้น)
- DOM-ACCESS-01 นักศึกษาเข้าดูรายการอุปกรณ์ได้เฉพาะภาควิชาของตนเอง (ปิด Q-03)
  นักศึกษาภาควิชาอื่นไม่เห็นรายการและรายละเอียดอุปกรณ์
- IF-IDP-01 ต้องได้รับผลยืนยันตัวตนจาก auth service ก่อนเข้าถึงข้อมูล (UC-13)
  และต้องได้รับข้อมูลภาควิชาของผู้ใช้จาก auth service เพื่อใช้ตรวจ DOM-ACCESS-01

## Requirements
- FR-EQS-01 ระบบต้องแสดงรายการอุปกรณ์แบบแบ่งหน้า โดย 1 แถวคือ 1 รุ่น/ชนิด
  แสดงชื่อรุ่น ประเภท และจำนวนที่พร้อมให้ยืม/จำนวนทั้งหมด
  เมื่อเลือกแถวแล้วแสดงอุปกรณ์รายชิ้นตามรหัสครุภัณฑ์ (CON-DATA-03)
  พร้อมสถานะล่าสุดของแต่ละชิ้น                                        <- UC-01 main flow ขั้น 3-4
- FR-EQS-02 ระบบต้องค้นหาอุปกรณ์จากชื่อหรือรหัสอุปกรณ์
  และกรองตามประเภทและสถานะได้                                       <- UC-01 main flow ขั้น 5-6
- FR-EQS-03 เมื่อค้นหาแล้วไม่พบข้อมูล ระบบต้องแจ้งว่าไม่พบอุปกรณ์
  พร้อมเสนอทางเลือกล้างตัวกรอง                                        <- UC-01 alternative 6a
- FR-EQS-04 เมื่ออุปกรณ์มีสถานะ "ถูกยืม" ระบบต้องแสดงกำหนดคืนโดยประมาณ
  และต้องไม่แสดงปุ่มส่งคำขอยืม                                         <- UC-01 alternative 8a
- FR-EQS-05 เมื่ออุปกรณ์มีสถานะ ชำรุด/ซ่อมบำรุง/สูญหาย ระบบต้องแสดงสถานะ
  ด้วยป้ายที่แยกออกจากกันชัดเจน และไม่อนุญาตให้ส่งคำขอยืม                  <- UC-01 alternative 8b
- FR-EQS-06 เมื่ออุปกรณ์มีสถานะ "พร้อมให้ยืม" ระบบต้องเปิดให้ส่งคำขอยืมต่อได้
  โดยส่งข้อมูลอุปกรณ์ที่เลือกไปยัง UC-02                                <- UC-01 alternative 8c
- FR-EQS-07 ระบบต้องแสดงข้อมูลตามสิทธิ์: เจ้าหน้าที่และอาจารย์เห็นชื่อผู้ยืมปัจจุบัน
  และสรุปจำนวนอุปกรณ์แยกตามสถานะ นักศึกษาไม่เห็น                       <- UC-01 alternative 3a
- FR-EQS-08 เมื่อดึงข้อมูลจากฐานข้อมูลไม่สำเร็จ ระบบต้องแจ้งข้อผิดพลาด
  พร้อมเปิดให้ลองใหม่ และต้องไม่แสดงข้อมูลเก่าที่อาจไม่ถูกต้อง               <- UC-01 exception E2
- FR-EQS-09 เมื่ออุปกรณ์มีสถานะ "รออนุมัติ" ระบบต้องแสดงป้ายสถานะแยกจากสถานะอื่น
  ไม่แสดงปุ่มส่งคำขอยืม และไม่นับรวมในจำนวนที่พร้อมให้ยืม
- FR-EQS-10 ระบบต้องอนุญาตให้นักศึกษาเข้าดูรายการอุปกรณ์เฉพาะภาควิชาของตนเอง (DOM-ACCESS-01)
  นักศึกษาภาควิชาอื่นต้องได้รับข้อความแจ้งว่าไม่มีสิทธิ์เข้าถึง และไม่ได้รับข้อมูลอุปกรณ์

## Quality Requirements
- NFR-PERF-01 การค้นหาและแสดงรายการอุปกรณ์: เวลาตอบสนอง p95 <= 2 วินาที
  ที่ข้อมูลอุปกรณ์ 1,000 รายการ และผู้ใช้พร้อมกัน 50 คน
- NFR-DATA-01 สถานะที่แสดงต้องคลาดเคลื่อนจากฐานข้อมูลจริงไม่เกิน 30 วินาที
- NFR-SEC-01 ข้อมูลเข้ารหัสขณะรับส่งด้วย TLS 1.2 ขึ้นไป และต้องผ่านการยืนยันตัวตนก่อนทุกครั้ง
- NFR-AVAIL-01 ระบบพร้อมใช้งานอย่างน้อย 99% ในช่วง 08.30-16.30 น. วันจันทร์-ศุกร์
- NFR-USE-01 ใช้งานได้บนหน้าจอมือถือ และผู้ใช้ใหม่ค้นหาสถานะอุปกรณ์ที่ต้องการได้
  ภายใน 1 นาที โดยผู้ทดสอบ 8 ใน 10 คนทำสำเร็จโดยไม่ต้องขอความช่วยเหลือ

## Acceptance Criteria
- [ ] AC-EQS-01 (FR-EQS-01)
      Given นักศึกษายืนยันตัวตนแล้ว และมีอุปกรณ์รุ่นหนึ่ง 5 ชิ้น พร้อมให้ยืม 3 ชิ้น
      When  เปิดหน้ารายการอุปกรณ์ แล้วเลือกรุ่นนั้น
      Then  รายการแสดงรุ่นนั้น 1 แถว ระบุประเภทและ "พร้อมให้ยืม 3 / ทั้งหมด 5"
            และเมื่อเลือกแล้วเห็นอุปกรณ์ 5 ชิ้นตามรหัสครุภัณฑ์พร้อมสถานะของแต่ละชิ้น
- [ ] AC-EQS-02 (FR-EQS-02)
      Given อยู่ในหน้ารายการอุปกรณ์
      When  ค้นหาด้วยคำว่า "Notebook" และกรองสถานะ "พร้อมให้ยืม"
      Then  แสดงเฉพาะอุปกรณ์ที่ชื่อหรือรหัสตรงกับคำค้น และมีสถานะพร้อมให้ยืมเท่านั้น
- [ ] AC-EQS-03 (FR-EQS-03)
      Given ค้นหาด้วยคำที่ไม่มีในระบบ
      When  กดค้นหา
      Then  แจ้งว่าไม่พบอุปกรณ์ และมีทางเลือกล้างตัวกรองกลับไปดูรายการทั้งหมด
- [ ] AC-EQS-04 (FR-EQS-04, CON-DATA-02)
      Given เจ้าหน้าที่บันทึกส่งมอบอุปกรณ์ชิ้นหนึ่งใน UC-08 แล้ว
      When  นักศึกษาเปิดดูอุปกรณ์ชิ้นนั้น
      Then  สถานะแสดงเป็น "ถูกยืม" พร้อมกำหนดคืนโดยประมาณ และไม่มีปุ่มส่งคำขอยืม
- [ ] AC-EQS-05 (FR-EQS-06, NFR-DATA-01)
      Given เจ้าหน้าที่บันทึกการคืนใน UC-09 สภาพปกติ
      When  นักศึกษารีเฟรชหน้ารายการภายใน 30 วินาที
      Then  สถานะเปลี่ยนเป็น "พร้อมให้ยืม" และปุ่มส่งคำขอยืมกลับมาใช้งานได้
- [ ] AC-EQS-06 (FR-EQS-05)
      Given อุปกรณ์มีสถานะ "ชำรุด"
      When  นักศึกษาเปิดดูรายละเอียด
      Then  แสดงสถานะชำรุดด้วยป้ายที่แยกจากสถานะอื่น และไม่มีปุ่มส่งคำขอยืม
- [ ] AC-EQS-07 (FR-EQS-07, DOM-PRIV-01)
      Given อุปกรณ์กำลังถูกยืมโดยนักศึกษาคนอื่น
      When  นักศึกษาทั่วไปเปิดดูรายละเอียด และเจ้าหน้าที่เปิดดูรายละเอียดเดียวกัน
      Then  นักศึกษาไม่เห็นชื่อผู้ยืม แต่เจ้าหน้าที่เห็นชื่อผู้ยืมปัจจุบัน
- [ ] AC-EQS-08 (FR-EQS-08)
      Given ฐานข้อมูลไม่ตอบสนอง
      When  เปิดหน้ารายการอุปกรณ์
      Then  แสดงข้อความผิดพลาดพร้อมปุ่มลองใหม่ ไม่แสดงหน้าจอค้างและไม่แสดงข้อมูลเก่า
- [ ] AC-EQS-09 (IF-IDP-01)
      Given session หมดอายุ
      When  เรียกดูรายการอุปกรณ์
      Then  ส่งกลับหน้าเข้าสู่ระบบพร้อมข้อความแจ้ง และกลับมาหน้าเดิมได้หลังล็อกอินสำเร็จ
- [ ] AC-EQS-10 (NFR-PERF-01)
      Given ข้อมูลอุปกรณ์ 1,000 รายการ และผู้ใช้พร้อมกัน 50 คน
      When  ค้นหาอุปกรณ์
      Then  p95 ของเวลาตอบสนอง <= 2 วินาที
- [ ] AC-EQS-11 (DOM-AUDIT-01)
      Given มีการเปิดดูรายละเอียดอุปกรณ์
      When  การเข้าถึงเสร็จสิ้น
      Then  มี audit log ที่ระบุผู้เข้าถึง เวลา และรหัสอุปกรณ์ที่เปิดดู
- [ ] AC-EQS-12 (FR-EQS-09)
      Given อุปกรณ์ชิ้นหนึ่งมีสถานะ "รออนุมัติ"
      When  นักศึกษาเปิดหน้ารายการและหน้ารายละเอียดของชิ้นนั้น
      Then  เห็นป้าย "รออนุมัติ" แยกจากสถานะอื่น ไม่มีปุ่มส่งคำขอยืม
            และจำนวนที่พร้อมให้ยืมของรุ่นนั้นไม่นับชิ้นนี้
- [ ] AC-EQS-13 (FR-EQS-10, DOM-ACCESS-01)
      Given นักศึกษาภาควิชา A ยืนยันตัวตนแล้ว และอุปกรณ์เป็นของภาควิชา B
      When  เปิดหน้ารายการอุปกรณ์ หรือเรียกรายละเอียดอุปกรณ์ของภาควิชา B โดยตรง
      Then  แจ้งว่าไม่มีสิทธิ์เข้าถึง และไม่มีข้อมูลอุปกรณ์ของภาควิชา B ถูกส่งกลับ

## Assumptions & Open Questions
- ASM-01 ข้อมูลอุปกรณ์ตั้งต้นถูกนำเข้าระบบโดยเจ้าหน้าที่ก่อนเปิดใช้งานจริง
- ASM-02 ระบบยืนยันตัวตนใช้บัญชีของมหาวิทยาลัยที่มีอยู่แล้ว ผ่าน auth service (UC-13)
- ASM-03 ประเภทอุปกรณ์ (category) อ่านจากข้อมูลที่เจ้าหน้าที่กำหนดไว้แล้วใน UC-10
- Q-01 [ปิดแล้ว 2569-09-20] นักศึกษาเห็น "กำหนดคืนโดยประมาณ" ตาม FR-EQS-04
  (ควรยืนยันกับเจ้าหน้าที่ภาควิชาอีกครั้งก่อน freeze spec)
- Q-02 ต้องมีฟังก์ชันจองล่วงหน้าสำหรับอุปกรณ์ที่ยังไม่ว่างหรือไม่?
  ถ้ามี ต้องเพิ่ม use case ใหม่ใน diagram -> ถามอาจารย์หัวหน้าโครงการ
- Q-03 [ปิดแล้ว 2569-09-20] เฉพาะนักศึกษาภาควิชานี้ ดู DOM-ACCESS-01, FR-EQS-10
- Q-04 ประเภทอุปกรณ์กำหนดตายตัว หรือให้เจ้าหน้าที่เพิ่มเองได้? -> ถามนักคอมพิวเตอร์
