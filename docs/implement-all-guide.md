# เรียง task ให้ทำต่อเนื่องได้: เฟสแนวตั้ง + /implement-all

คู่มือนี้อธิบายคำสั่ง 2 ตัวใน agent-pack รุ่นที่ 2
- `/tasks` (รุ่นใหม่) แตก plan.md เป็นเฟสแนวตั้ง 1 เฟสต่อ 1 เรื่องที่ผู้ใช้ทำได้ พร้อมจุดตรวจท้ายเฟส
- `/implement-all` ทำ task ต่อเนื่องทีละตัวจนจบ 1 เฟส commit ทีละ task แล้วหยุดที่จุดตรวจ

## 1. ทำไมต้องเรียงแบบเฟสแนวตั้ง

| | เรียงแบบชั้น (แบบเดิม) | เรียงแบบเฟสแนวตั้ง (แบบใหม่) |
|---|---|---|
| ลำดับ | ฐานข้อมูลทั้งหมด แล้ว API ทั้งหมด แล้วหน้าจอทั้งหมด | 1 เฟส = 1 เรื่องที่ผู้ใช้ทำได้ ทำครบทั้งเส้น หลังบ้าน แล้วหน้าจอ |
| เห็นระบบใช้งานได้จริงเมื่อไหร่ | ตอนท้ายสุด | ทุกครั้งที่จบเฟส |
| ถ้าเข้าใจความต้องการผิด | รู้ตอนท้าย แก้ยาก | รู้ตั้งแต่เฟสแรก แก้แค่เฟสเดียว |
| task เชื่อมหน้าจอกับหลังบ้าน | ต้องแยก task ต่อ API จริงไว้ท้ายสุด | ไม่ต้องแยก จุดตรวจของเฟสลองของจริงให้ |
| ตรวจกับ AC | ต้องรอทุกชั้นเสร็จ | ตรวจ AC ได้ทันทีที่จบเฟสของมัน |

แนวคิดเดียวกับ user story ใน Agile และการแบ่ง phase ต่อ user story ใน GitHub Spec Kit

## 3. /implement-all ทำงานอย่างไร

```
/implement-all specs/001-booking/tasks.md เฟส 1
```

1. เช็กว่าเฟสก่อนหน้าผ่านจุดตรวจแล้ว (ทุก task สถานะ "เสร็จ") และรัน test เดิมทั้งหมดให้ผ่านก่อนเริ่ม
2. ทำ task ในเฟสทีละตัวตามลำดับ กติกาเดียวกับ /implement ทุกข้อ
3. จบแต่ละ task รัน **test ทั้งหมดของโปรเจกต์** เพื่อเช็กว่าไม่ทำของเดิมพัง
4. ผ่านแล้ว commit ทีละ task (ไม่ push) ถ้าผิดทีหลังย้อนได้ทีละ task
5. จบเฟส หยุดที่จุดตรวจ แล้วคัด Given / When / Then มาให้คนลองเอง

## 4. เงื่อนไขที่ AI ต้องหยุดทันที

- test ไม่ผ่านหลังแก้ 3 รอบ
- test เดิมที่เคยผ่านกลับพัง
- เจอ task "รอ Q-xx"
- ต้องเดาสิ่งที่ spec และ plan ไม่ได้บอก
- ต้องแตะไฟล์นอกช่อง "ไฟล์ที่แตะ"
- ทำไปแล้ว 5 task ในรอบนี้
- จบเฟส (ถึงจุดตรวจ)

AI ห้ามเริ่มเฟสถัดไปเอง คนต้องผ่านจุดตรวจก่อนเสมอ

## 5. ที่จุดตรวจ คนทำอะไร

1. อ่านรายงาน ดูตาราง task ไฟล์ที่แตะ test และ commit
2. เปิดระบบตามคำสั่งในบล็อกจุดตรวจ (terminal 1 หลังบ้าน terminal 2 หน้าจอ)
3. ลองเองตาม Given / When / Then ของ AC ในเฟสนั้น
4. ผ่าน: เปลี่ยนสถานะ task ในเฟสเป็น "เสร็จ" แล้ว `git add -A && git commit -m "เฟส N ผ่านจุดตรวจ" && git push` แล้วค่อยสั่งเฟสถัดไป
5. ไม่ผ่าน: `git log --oneline` ดูว่า commit ไหนผิด แล้วแก้ทีละ task ด้วย /implement หรือย้อนด้วย `git revert <รหัส commit>`

## 6. ใช้ /implement หรือ /implement-all

| สถานการณ์ | ใช้ |
|---|---|
| ครั้งแรกที่เรียน หรือ task ที่ยาก | /implement ทีละตัว ดูทุกไฟล์ |
| task ในเฟสเล็ก ชัดเจน มี AC ครบ | /implement-all ทีละเฟส |
| AI ทำผิดซ้ำใน /implement-all | กลับไปใช้ /implement ทีละตัว |

เรื่อง credits: 1 รอบของ /implement-all ใช้ credits ประมาณเท่ากับสั่ง /implement ทีละตัวรวมกัน บวกกับรัน test ทั้งหมดทุก task แผน Copilot Student ได้ 200 credits ต่อเดือน ให้เลือกโมเดล Auto และทำทีละเฟส

## 7. ต่างจาก /speckit.implement ของ Spec Kit อย่างไร

Spec Kit ทำ task ทั้งหมดตามเฟสต่อเนื่องไปจนจบ ส่วน /implement-all ของรายวิชา**บังคับหยุดทุกเฟส**ให้คนตรวจกับ AC ก่อน เพราะวิชานี้เน้นให้คนเป็นผู้ตัดสินว่าความต้องการถูกทำให้เป็นจริงแล้วหรือยัง
